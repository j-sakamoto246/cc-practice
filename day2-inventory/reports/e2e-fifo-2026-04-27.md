# E2E テスト: FIFO ロット管理・出庫機能

実行日: 2026-04-27
DB: `data/inventory.db`（実行前に削除して初期状態から）
コマンド: 全て `npm run dev -- ...`

## シナリオ

商品 `MILK-1`（牛乳1L）について、期限の異なる 2 ロットを入庫し、FIFO 出庫・倉庫間移動・期限切れアラート・在庫不足エラーを通しで検証する。

| ロット | 期限 | 入庫量 | 期限までの日数 |
| --- | --- | --- | --- |
| A | 2026-05-30 | 10 | 33 日 |
| B | 2026-05-15 | 10 | 18 日 |

期待挙動: B の方が期限が早いので、入庫順で A が先でも B から先に消費される。

## 6. FIFO 出庫: 12 個

B(10) で足りない分を A から 2 個追加で取る複数ロット出庫。

```bash
$ npm run dev -- stock out --sku MILK-1 --warehouse 東京倉庫 --quantity 12 --note ord-E2E-001
[INFO] 出庫しました: product=..., warehouse=wh-tokyo, quantity=12, lots=2
出庫しました: MILK-1 x 12 ← 東京倉庫
```

ログの `lots=2` から 2 ロットにまたがる出庫だったことが確認できる。

### stock_movements の中身（sqlite3 で確認）

```sql
SELECT sm.type, sm.quantity, l.lot_code, sm.reference_id
FROM stock_movements sm
LEFT JOIN stock_lots l ON l.id = sm.lot_id
JOIN products p ON p.id = sm.product_id
WHERE p.sku = 'MILK-1'
ORDER BY sm.created_at, sm.id;
```
```
type  quantity  lot_code  reference_id
----  --------  --------  ------------
in    10        A
in    10        B
out   10        B         ord-E2E-001
out   2         A         ord-E2E-001
```

✅ 12 個の出庫が `B から 10 + A から 2` の 2 行に分割記録されており、両方とも `reference_id = ord-E2E-001` で紐づいている。

### 出庫後のロットと在庫

```bash
$ npm run dev -- stock lots --sku MILK-1
 SKU    | 倉庫   | ロット | 残量 | 期限         | 入庫日時
--------+------+-----+----+------------+--------------------------
 MILK-1 | 東京倉庫 | A   | 8  | 2026-05-30 | 2026-04-27T09:45:50.098Z

$ npm run dev -- stock status --sku MILK-1
 SKU    | 商品名  | 倉庫   | 数量
--------+------+------+----
 MILK-1 | 牛乳1L | 東京倉庫 | 8
```

✅ B は枯渇し（既定で非表示）、A は 8 残。`inventory.quantity = 8 = SUM(lots.quantity_remaining)` の不変条件が成立。

## 7. 出庫後の期限切れアラート再評価

```bash
$ npm run dev -- stock expiring --days 30
期限が30日以内のロットはありません

$ npm run dev -- stock expiring --days 60
 SKU    | 倉庫   | ロット | 残量 | 期限         | 残日数
--------+------+-----+----+------------+-----
 MILK-1 | 東京倉庫 | A   | 8  | 2026-05-30 | 33
```

✅ B が消費されたので 30 日アラートは空。`--days 60` に広げると A がヒットする（33 日）。

## 8. 倉庫間移動（期限保持の確認）

東京倉庫 → 大阪倉庫 へ 5 個移動。

```bash
$ npm run dev -- stock transfer --sku MILK-1 --from 東京倉庫 --to 大阪倉庫 --quantity 5
[INFO] 在庫移動しました: ..., quantity=5, lots=1
在庫を移動しました: MILK-1 x 5 東京倉庫 → 大阪倉庫

$ npm run dev -- stock lots --warehouse 大阪倉庫
 SKU    | 倉庫   | ロット | 残量 | 期限         | 入庫日時
--------+------+-----+----+------------+--------------------------
 MILK-1 | 大阪倉庫 | A   | 5  | 2026-05-30 | 2026-04-27T09:46:26.949Z
```

✅ 移動先には移動元の `lot_code = A` と `expiry = 2026-05-30` を引き継いだ新規ロットが作成された。

## 9. 在庫不足エラー

東京倉庫の残量は `8 - 5(移動) = 3`。100 個出庫を試みると失敗する。

```bash
$ npm run dev -- stock out --sku MILK-1 --warehouse 東京倉庫 --quantity 100
エラー: 在庫不足です: 現在庫=3, 要求=100
exit_code=1
```

✅ `InsufficientStockError` が現在庫量とともに正しくレポートされ、exit code 1 で異常終了。

## 10. 最終在庫

```bash
$ npm run dev -- stock status
 SKU    | 商品名  | 倉庫   | 数量
--------+------+------+----
 MILK-1 | 牛乳1L | 大阪倉庫 | 5
 MILK-1 | 牛乳1L | 東京倉庫 | 3
```

合計 8 個（最初に入庫した 20 個 - 出庫 12 個）。総量保存則も成立。
